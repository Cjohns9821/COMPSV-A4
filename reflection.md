For my timed challenge, I chose the “First Repeated Value” problem. 
I selected a set as the core data structure because it provides constant‑time membership checks, which makes it ideal for detecting duplicates efficiently. 
As I iterated through the list, the set allowed me to immediately identify when a value had already appeared, ensuring the solution ran in linear time. 
This structure kept the implementation simple, readable, and optimal for the problem’s requirements.

The 30‑minute time limit influenced my decision significantly. 
Under time pressure, choosing a structure that is both familiar and efficient is essential. 
A set is straightforward to use and avoids the complexity of alternative approaches like nested loops or dictionaries with counters. 
The time constraint pushed me toward a solution that minimized cognitive overhead while still meeting performance expectations. 
I focused on correctness first, then expanded into edge‑case testing once the core logic was complete.

I made a few trade-offs during the challenge. 
I prioritized clarity and reliability over exploring more elaborate or memory‑optimized solutions. 
Using a set does require additional space proportional to the number of unique elements, but this trade-off was acceptable given the simplicity and speed benefits. 
I also chose to test a wide range of edge cases—including empty lists, single-element lists, immediate repeats, mixed data types, and negative numbers—to ensure the function behaved correctly across realistic inputs. 
Overall, the challenge reinforced the importance of selecting the right data structure quickly and confidently under time constraints.
